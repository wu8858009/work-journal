# 工作週誌：搬到 Google 試算表

跟油耗 App 一樣的作法：網頁放在 GitHub Pages，資料存在你自己的 Google 試算表（Apps Script 當後端）。
不需要開電腦，也不會像 Render 免費版那樣睡著、第一次開要等一分鐘。

## 第一次設定（約 5 分鐘）

1. 開 <https://sheets.new> 建立新試算表，命名「工作週誌 雲端資料」。
2. 選單「擴充功能 → Apps Script」，刪掉原本的內容，把 `cloud/Code.gs` 整份貼上，按儲存（💾）。
3. 右上「部署 → 新增部署作業」，齒輪選「網頁應用程式」：
   - 執行身分：**我**
   - 誰可以存取：**所有人**
   - 按「部署」，第一次會要求授權：選你的帳號 →
     若出現「Google 尚未驗證這個應用程式」→「進階」→「前往（不安全）」→「允許」。
4. 複製「網頁應用程式網址」（`https://script.google.com/macros/s/…/exec`）。

## 搬資料、切換

5. 把舊資料搬過去（只讀 MongoDB，雲端還沒有帳號時才接受）：

   ```
   cd backend\WorkJournalApi
   python ..\..\cloud\migrate_from_mongo.py appsettings.Production.json WorkJournalDb <網址>
   ```

   帳號密碼原封不動搬過去，大家用原本的密碼登入即可。
6. 把網址填進 `config.js` 的 `window.WJ_CLOUD_URL`，再發佈網頁（GitHub Pages）。
7. 桌面版：把前端檔案（含 `config.js`）複製到 `portable\`，重新開啟 `工作週誌.exe`。

## 之後更新後端程式碼

Apps Script 貼上新版 `Code.gs` → 儲存 →「部署 → 管理部署作業 → ✏ 編輯 → 版本：新版本 → 部署」。網址不會變。

## 資料存放方式

| 工作表 | 內容 |
|---|---|
| Users / Departments | 帳號（密碼只存雜湊）、餐廳 |
| Journals | 週誌（不含照片） |
| Photos | 照片，一張一列；存檔時只寫新增或改過的照片 |
| LightTimers / Maintenance | 每間餐廳的定時器、保養排程 |
| AuditLogs / PasswordResets / Settings | 稽核紀錄（保留最新 1000 筆）、忘記密碼申請、系統設定 |

每格開頭的 `~` 是為了不讓試算表把內容自動轉成數字或日期，**請不要手動修改這些工作表**。
「誰在線上」放在 Apps Script 快取，不寫進試算表。

## 限制

- 每次存檔約 1～3 秒（Render 醒著時比較快，但不會再有睡著要等一分鐘的情況）。
- 試算表沒有容量問題；照片很多（上千張）時讀取會慢一些。
- 同時最多約 30 個請求，十幾個人同時使用沒問題。
